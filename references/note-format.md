# 笔记格式与领域归类

## 按领域组织，按主题成篇
自主判断所属学科或工程领域，用少量清楚的目录，例如 `硬件/电机.md`、`硬件/通信接口.md`、`软件/异步IO.md`。跨领域内容选择主要归属，用链接联系其他领域，不必为所有方向预建空目录。

适合共同理解、比较的概念放进一篇主题笔记，用小节区分。PMSM、步进电机和舵机归于电机学与运动控制，共同放在 `硬件/电机.md`；仍需说明前两者主要描述电机本体，舵机描述集成执行机构。不要把同篇内容误当同义词。

同义名称只维护一处解释。每个小节通常数百字以内，复杂度决定长度，不硬凑字数。主动按内容需要整理和拆分，不要求用户逐次指示；同篇归并是可调整的起点，不是永久约束。已有有效笔记保留内容，不机械套模板。

## 结构整理的判断
- **拆分：** 一篇出现多个独立主题，详细推导或实现掩盖概览，某部分经常被跨主题引用，或读者难以快速定位所需内容时，考虑独立成篇。例如电机类型对比留在“电机”，FOC、通用反馈控制和通信在内容充分时可独立成主题。
- **合并：** 多篇过短、解释重复，或必须一起比较才能理解时，合为一个清楚的主题。没有查找或理解收益时不为拆分而拆分。
- **目录：** 主要按学科或工程领域组织；一层目录已清楚时不增加层级。跨领域知识放在最适合的主要位置，其余位置用链接关联。
- **拆分结果：** 原主题保留简短概览和到新文件的入口；完整定义、公式、图和解释迁移到主要位置，不两处复制维护。同步修复原文件的小节入链、首页、导航和资源路径。
- **收尾：** 简述主要结构变动和查找入口，不生成历史日志，不随任务扩大为整个知识库的无关重构。

## 词典式解释
先给定义，再给必要解释。定义用“类别＋区别性特征”，一至两句直接回答是什么；原理写清因果，应用说明具体用途，交互说明输入、处理和输出。保留适用条件，不能为简短而删去关键区别。不写聊天式引导、夸张评价、反复总结或拟人化比喻；例子只用于澄清抽象内容，不强制每个概念都套五个空栏目。

例如：**PWM（脉冲宽度调制）是一种通过改变周期性脉冲的占空比，调节开关电路平均输出的调制方法。** 电机驱动器利用 PWM 控制功率开关的导通时间，从而调节绕组电压；电流还取决于绕组参数、反电动势和反馈控制。

又如：**PI控制器是一种将当前误差的比例项与误差的积分项相加，生成控制输出的反馈控制器。** 比例项响应当前误差，积分项累计误差；在FOC电流环中，它根据电流误差生成电压指令。

## 写作结构
```markdown
# 主题名称
一句话说明所属领域、解决的问题和分类边界。

## 子概念名称
**定义：** 所属类别与区别性特征，保留英文名或缩写。
**原理：** 简短因果链，必要时解释公式中的量和条件。
**实际用途：** 一个具体工程场景及主要限制。
**组件交互：** 谁提供输入、谁处理、谁消费输出；区分数据、信号和电能。
**易混淆点：** 和相近概念的关键区别。

## 对比与关联
用表格比较同篇子概念；跨主题关系写清依赖、实现或交互。
```

默认不生成来源、参考资料或外部引用栏目。具体型号、引脚、参数、API 和协议版本仍需核验，未知内容明确待确认。只保留真实存在的内部链接，不为凑关联创建空笔记。

文件级 aliases 只收录整个主题的同义名，不把所有子概念都当成主题别名。链接子概念使用 `[[硬件/电机#PMSM|PMSM]]` 这样的标题锚点。正文保留英文名称供搜索。

## 图示与导航
用小型 Mermaid 图解释控制、数据、能量或依赖关系，边标明含义；图不能替代原理。不要把同一领域误画成一条信号链，也不要把示意图当接线图。普通 Markdown、双向链接和 Mermaid 即可，不要求第三方插件。

首页直接链接领域下的主题笔记及关键小节。只有导航复杂时才增加领域或主题索引，不重复抄写正文。首页可保留当前待弄清的问题，不记录日志、复盘、提问次数、时长或历史趋势，也不推断掌握程度。

## 术语与边界
- AMD64 与 x86-64 可归一；x86 可能指家族或 32 位语境，不能全部合并。
- arm63 应确认是否想问 ARM64/AArch64，不静默纠正。
- ASIO 缺少语境时先区分音频驱动接口与 C++ 异步 I/O 库。
- FOC 是控制方法，MCU 是器件类别；可在相关主题的小节分别解释，不混淆职责。
- “英飞凌通信模块”缺少型号时不猜测接口、引脚和电气参数。

## 合并与移动
使用 UTF-8。写入前重新读取当前内容，保留手写内容和其他工具的修改。合并时搜索所有入链，兼顾完整路径、短链接、显示别名、标题/块锚点、图片嵌入和相对路径。

先写新主题，再修复旧文件与旧标题到新小节的链接，校验目标和锚点后移除冗余旧文件。文件系统移动不会自动修复 Obsidian 链接。中途失败则保留可恢复原文件并报告，不继续删除；无法判断的内容冲突保留并说明。不修改 `.obsidian` 配置。
